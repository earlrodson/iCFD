## Description
Full-corpus audit of all 103 published EN `topics` rows against four quality
dimensions: (1) comprehensive `answer_full` vs `answer.summary`-only content,
(2) whether `scripture`/`catechism`/`church_fathers`/`objections` entries
actually align with claims made in the prose (vs bolted-on/generic/missing),
and (3) overall theological accuracy and finish. Run via a 103-agent workflow
(one per topic, each reading the live Supabase row) on 2026-09-01. Findings
below are a backlog for a future content-enhancement session — no content was
changed by this audit.

## Traceability & Technical Intent
- **Outcome / Strategy Alignment:** Raises topic content up to the "comprehensive,
  well-sourced, objection-aware" bar the content-generation pipeline
  (`tools/generate-topic.ts`) already targets for new topics, closing the gap
  for topics seeded/written before that pipeline existed.
- **Technical Intent:** Structural data gap — many topics have prose that
  already contains material (patristic quotes, objections, extra scripture)
  that was never extracted into the corresponding jsonb column, plus a
  smaller set of topics that are genuinely stub-length and need real
  `generate-topic.ts` runs.
- **Benefit Hypothesis:**
  - *By implementing:* the enhancement todos below (metadata backfill for
    high scorers, full pipeline re-runs for low scorers)
  - *We will improve:* per-topic content depth and citation/section
    trustworthiness across the app
  - *As measured by:* quality_score distribution shifting from today's
    baseline (2:26, 3:40, 4:35, 5:2) toward 4-5
    across all 103 topics

## Platform & Operating Context
- **Ecosystem Context:** Supabase `topics` table (`gdobgalhdepfpxexssvq`),
  `tools/generate-topic.ts` (qwen3:14b generation / qwen3.5:9b extraction
  split, see project CLAUDE.md), `tools/vector-search-theology.ts` for
  grounding new Church Father / CCC citations.
- **Operating Context:** EN rows only audited (103 of 103). CEB/TL rows for
  the same topic ids were not evaluated in this pass — translations inherit
  whatever gaps exist in the EN source, so fixing EN first is the correct
  order.
- **Regulatory Context:** None — content-quality change, no schema/RLS impact.

## Behavior Specifications

```gherkin
Scenario: A topic flagged as concise-only gets a comprehensive rewrite
  Given a topic row with no `answer_full` (or under ~100 chars)
  When generate-topic.ts Phase 2 is run for that topic id
  Then answer_full contains a 1500-2500 word article consistent with the
    existing answer.summary, and the topic's quality_score on re-audit is >= 4

Scenario: A topic's structured sections are backfilled from existing prose
  Given a topic whose answer_full already quotes a Church Father, CCC
    paragraph, or scripture verse not present in the matching jsonb column
  When that citation is extracted into the correct column
  Then the column's entries all correspond to citations actually used in
    the prose, with no orphaned or missing references
```
